# TrayBin v2.1.4 — аудит Lean Runtime

## Факты из исходников 2.1.3
- WebView-окон нет, три команды доступны через нативное меню трея.
- Каждые 5 секунд используется `SHQueryRecycleBinW` для быстрой проверки количества/размера.
- Полный снимок перечитывается при изменении или каждые 60 секунд.
- До оптимизации копия полного `Snapshot` сохранялась в `Cache` и клонировалась при каждом опросе: в ней есть список `Volume`, строки и сведения автозапуска, которые для сравнения не используются.

## Изменение 2.1.4
`Cache` хранит только три скалярных поля: `available`, `items`, `size`.
Полный `Snapshot` остаётся локальным в обновлении значка и подсказки и не клонируется в кэш.
Частота опроса 5 секунд, полное обновление 60 секунд, пять иконок, ЛКМ/двойной ЛКМ, меню ПКМ и системная очистка не изменены.
Вспомогательные файлы старой HTML-панели сохранены на диске для совместимости/отката.

## Ограничения проверки
JavaScript-контрактные тесты проверяют исходники; они не заменяют Windows Release/Rust проверки.
Ожидаемое снижение аллокаций и памяти кэша небольшое: нельзя заявлять измеренный выигрыш RAM/CPU без замеров на Windows 11.
Новый код Rust должен пройти компиляцию на целевом компьютере до признания версии стабильной.

## Что стоит профилировать позже
- Потребление Working Set и PrivateMemorySize64 в простое.
- Реальные затраты 5-секундного Shell-опроса и 60-секундной полной инвентаризации.
- Влияние фонового опроса на подключённые внешние/сетевые тома.
Не снижать частоту обновления без измерений и согласования: это влияет на отзывчивость значка.
